AI Image Search — หลักการทำงาน

ระบบ Image Search ทำงานยังไง อธิบายแบบง่าย
ระบบแปลงรูปภาพให้เป็นตัวเลขชุดหนึ่ง (vector) แล้ววัดว่า "รูปค้นหา" กับ "รูปในโพส" ห่างกันแค่ไหน รูปที่ใกล้กันที่สุด = คล้ายกันมากที่สุด 
ขั้นตอนเมื่อผู้ใช้อัปโหลดรูปโพส:
1. รับรูปจากผู้ใช้
2. บีบอัดรูป (ลด size, JPEG 82%)
3. ส่งเข้า ResNet50 model → ได้ vector 2048 มิติ
4. จำแนกประเภทสัตว์ (สุนัข/แมว/นก ฯลฯ)
5. บันทึก vector + รูป + ข้อมูลลง PostgreSQL

ขั้นตอนเมื่อผู้ใช้ค้นหา:
1. รับรูปค้นหา
2. แปลงเป็น vector เช่นกัน
3. ใช้ CosineDistance() เปรียบเทียบกับทุก vector ในฐานข้อมูล
4. เรียงจากคล้ายมาก → คล้ายน้อย
5. แสดงผล top 24 พร้อมเปอร์เซ็นต์ความคล้าย
ทำไมถึงเลือกใช้ ResNet50
— เป็น model มาตรฐานที่ถูกเทรนบน ImageNet (14 ล้านรูป, 1000 class)
— มีน้ำหนัก (weights) สำเร็จรูปให้ดาวน์โหลดฟรีผ่าน torchvision
— ขนาด ~100 MB เหมาะกับ free tier
— vector 2048 มิติ ให้ feature ที่ละเอียดกว่า CLIP (512 มิติ)
Cosine Distance คืออะไร
วัดมุมระหว่าง vector 2 ตัว
— ค่า 0 = เหมือนกัน 100%
— ค่า 1 = ตรงข้ามกัน 0%
ระบบแสดงเป็น % โดย similarity = (1 - distance) × 100
AI จำแนกประเภทสัตว์ยังไง
ResNet50 ทำนาย class จาก ImageNet 1000 class
ระบบ map class index → ประเภทสัตว์ เช่น
class 151-268 = สุนัข, class 281-285 = แมว, class 7-24 = นก
โค้ดอยู่ใน pet_core/utils.py ฟังก์ชัน _idx_to_pet_type()

Vector คืออะไร และทำงานยังไง

Vector คืออะไร อธิบายแบบเข้าใจง่าย
Vector คือการแปลงรูปภาพให้เป็น "พิกัด" ในพื้นที่ 2048 มิติ
รูปที่หน้าตาคล้ายกัน → พิกัดอยู่ใกล้กัน
รูปที่แตกต่างกัน → พิกัดอยู่ห่างกัน 
ตัวอย่าง (ย่อให้เหลือ 5 มิติเพื่อให้เข้าใจ):

สุนัขดำ A:  [0.91, 0.23, -0.45, 0.67, 0.12]
สุนัขดำ B:  [0.89, 0.25, -0.43, 0.65, 0.11]  ← ใกล้มาก → similarity สูง
แมวขาว:    [-0.32, 0.78, 0.91, -0.12, 0.55]  ← ห่างมาก → similarity ต่ำ
ไอโฟน:     [0.05, -0.88, 0.34, -0.71, 0.92]  ← ห่างมากที่สุด

ระบบนี้ใช้ 2048 มิติ (ละเอียดกว่า 400 เท่า)
Vector เก็บที่ไหนใน Database
ตาราง pet_core_petimage คอลัมน์ feature_vector
ชนิดข้อมูลเป็น vector(2048) ซึ่งเป็น type พิเศษของ pgvector extension

AI ดูรูปกี่รูปต่อโพส

AI ดูแค่รูปแรกหรือทุกรูป
ดูทุกรูปครับ — แต่ละรูปถูก embed เป็น vector แยกกันทั้งหมด
ตัวอย่าง: โพสมี 3 รูป
  รูป 1 (หน้าตรง)  → vector_1 → บันทึกลง DB
  รูป 2 (ด้านข้าง) → vector_2 → บันทึกลง DB
  รูป 3 (วิ่งอยู่)  → vector_3 → บันทึกลง DB

ตอนค้นหา:
  query_vector เทียบกับ vector_1, vector_2, vector_3
  เอา "คะแนนดีที่สุด" ของโพสนั้นมาแสดง
  ถ้าหลายรูป match → ได้ bonus score เพิ่ม
ทำไมถึงออกแบบแบบนี้ ไม่ดูแค่รูปแรก
เพราะคนที่เจอสัตว์หายอาจถ่ายคนละมุมกับเจ้าของ
ถ้าดูแค่รูปแรก (หน้าตรง) แต่คนค้นส่งรูปด้านข้างมา → หาไม่เจอ
การ embed ทุกรูปให้โอกาส match จากมุมกล้องใดก็ได้
โพสซ้ำๆ แก้ยังไง
ระบบ group ผลลัพธ์ตาม post_id ก่อน → เก็บแค่รูปที่ดีที่สุดต่อโพส
ถ้าเจ้าของโพสสัตว์ตัวเดิมหลายครั้ง → ใช้ rule: ถ้าชื่อเดียวกัน + similarity ≥ 95% → แสดงแค่อันดับ 1

Memory / RAM และข้อจำกัด Server

ส่วนใช้ RAMหมายเหตุ
Django + dependencies~80 MBปกติ
ResNet50 model~100 MBโหลดครั้งเดียวตอน start
อื่นๆ (pgvector, requests)~20 MB
รวม~200 MB
Render Free Limit512 MBเหลืออีก ~312 MB
Render กับ Supabase ต่างกันยังไง
Render = เซิร์ฟเวอร์ที่รัน Django code, AI model, logic ทั้งหมด → ใช้ RAM
Supabase = ฐานข้อมูล PostgreSQL + เก็บรูปภาพ → ใช้ Storage ไม่ใช่ RAM ของ Render
CPU Limit 0.15 CPU หมายความว่าอะไร
Render Free ได้ shared CPU น้อยมาก → ตอน AI ประมวลผลรูปอาจช้า 3-5 วินาที
ถ้า deploy จริงบน paid tier หรือ GPU server จะเร็วกว่านี้มาก
ถ้าเว็บไม่ตอบสนอง 30-50 วินาทีแรก = Render "spin up" เพราะ free tier หยุดเองตอนไม่มีคนใช้

ข้อจำกัดของระบบ (Limitations)

ข้อจำกัดสาเหตุแก้ได้ในอนาคต
ค้นรูปช้า 3-5 วินาทีCPU จำกัดบน free tierอัปเกรด server หรือใช้ GPU
เว็บ spin up นานRender free ปิดตัวเองเมื่อไม่มีคนpaid tier ไม่มีปัญหานี้
ค้นหาข้ามสายพันธุ์ได้ResNet50 ไม่ได้เทรนเฉพาะสัตว์เปลี่ยนเป็น DINOv2 หรือ fine-tuned model
รูปคนหรือวัตถุอาจขึ้นผลไม่มี threshold ตัดต่ำกว่า 30%เพิ่ม threshold filter
รองรับรูปสูงสุด 10MBจำกัด upload sizeปรับ config ได้
ข้อมูลจริงในระบบยังน้อยเพิ่งเปิดใช้งานเพิ่มขึ้นตามผู้ใช้
การยอมรับ limitation แสดงให้เห็นว่าเข้าใจระบบจริงๆ ไม่ใช่แค่ทำตาม tutorial

คำถามที่อาจารย์มักถาม

ทำไมเลือกใช้ Django ไม่ใช้ FastAPI หรือ Flask
Django มี ORM, Admin panel, Auth system พร้อมใช้ทันที ลดเวลา development มาก
FastAPI เหมาะถ้าต้องการ pure API, Flask เหมาะสำหรับ project เล็ก
Django เหมาะสำหรับ full-stack web app ที่ต้องการความสมบูรณ์
ทำไมใช้ PostgreSQL ไม่ใช้ MySQL หรือ SQLite
เพราะต้องการ pgvector extension ซึ่งมีเฉพาะ PostgreSQL
pgvector เพิ่มชนิดข้อมูล vector และ Cosine Distance query ที่จำเป็นสำหรับ Image Search
MySQL และ SQLite ไม่รองรับ vector search
ถ้ามีผู้ใช้เยอะๆ ระบบจะรองรับได้ไหม
ปัจจุบัน: Render Free — รองรับได้ประมาณ 10-20 concurrent users
ถ้าต้องการ scale: เพิ่ม Render instance หรือเพิ่ม index บน pgvector (HNSW index)
Database Supabase Free รองรับ 500MB storage และ 2 concurrent connections
Image Search แม่นแค่ไหน ทดสอบยังไง
ทดสอบโดยใช้รูปเดียวกับที่โพสไว้ → ได้ similarity 99%+
รูปมุมต่างออกไปของสัตว์เดิม → ได้ 60-80%
สัตว์ต่างสายพันธุ์ → ได้ต่ำกว่า 40%
รูปที่ไม่ใช่สัตว์ → ได้ต่ำกว่า 20-30%
ทำไมใช้ Cosine Distance ไม่ใช้ Euclidean Distance
Cosine วัดมุม — ไม่สนใจขนาด สนใจแค่ทิศทาง
เหมาะกับ image feature เพราะรูปที่ถ่ายใกล้/ไกล หรือ normalize แล้ว ยังเปรียบเทียบได้ถูกต้อง
Euclidean ไวต่อขนาด vector — ถ้า normalize ไม่ครบจะ bias ผลลัพธ์
ระบบ authentication ทำงานยังไง
ใช้ Supabase Auth (email/password) → Supabase ออก JWT token
Django middleware อ่าน token จาก cookie → verify กับ Supabase → สร้าง session
Django session ใช้สำหรับ login state ภายใน app
ข้อมูลส่วนตัวของผู้ใช้ปลอดภัยไหม
เบอร์โทรและ social link ถูก mask สำหรับผู้ที่ยังไม่ login
ต้อง login ก่อนจึงจะเห็นข้อมูลติดต่อเต็ม
รหัสผ่านเก็บโดย Supabase Auth (bcrypt hash) ไม่ได้เก็บใน database ของเราโดยตรง
ระบบนี้ต่างจาก Facebook Group หรือ Pantip ยังไง
จุดต่างหลัก: Image Search
Facebook/Pantip ค้นหาได้แค่ keyword เช่น "สุนัขสีดำหาย ลาดพร้าว"
ระบบนี้ถ่ายรูปแล้วค้นได้เลย — คนที่เจอสัตว์ไม่รู้ชื่อ ไม่รู้สายพันธุ์ ก็ค้นได้
+ มีแผนที่แสดงจุด + ระบบแจ้งหา/พบในที่เดียว
